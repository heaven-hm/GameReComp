# GitHub Issues Audit (`#1`–`#25`)

Audit of all **25 open issues** in [`heaven-hm/GameReComp`](https://github.com/heaven-hm/GameReComp/issues) against the `develop` branch codebase, `runtime/win32hle` C selftests (`14` suites), Python test suite (`tests/`, `170` baseline tests), Rust test suite (`src/`, `34` tests), Desktop GUI (`gui/` + `src/gui/`), WebAssembly core (`wasm32-unknown-unknown`), and the measured corpus matrix (`docs/GAME_MATRIX.md`, `reports/games/results.json`).

> **Honest evidence rule:** Every status classification below distinguishes **implemented infrastructure / passing unit tests / `PARTIAL` native boots** from **complete issue closure**. Across `#1`–`#25`, **zero issues are 100% complete**, because closed exit criteria explicitly require independent original-Windows gameplay scenario oracles (`PASS`), general D3D8/9/10/11 backends, arbitrary multi-DLL code lifting, or production Win16/Win64 pipelines.

## Detailed Notes by Group

### Core Toolchain, Decompilers & Verification (`#1`, `#3`, `#4`, `#14`, `#25`)
- **What is genuinely working today:**
  - `tools/autorecomp/pipeline.py` runs end-to-end across `inspect → recover → translate → project → compile → run → verify → report`.
  - Both Rust frontends (`src/bin/game-recomp-gui.rs` built with `gpui-kit = "0.10.0"`, and `src/bin/game-recomp-cli.rs` + `wasm32` library target `src/lib.rs`) are live on `develop`, with PE32 x86 validation (`src/pe.rs`), cycle-safe batch traversal (`src/tasks.rs`), and WASM local preview serving.
  - Honest verification strictly separates `PARTIAL` (process compiles cleanly and runs natively without crash) from `PASS` (requires an independent original-Windows gameplay oracle).
  - Baseline Corpus State before Phase 3 fixes (`335adc9`): **`93 / 120`** measured executables launch natively on macOS `arm64`, **`93`** with `0` unresolved imports (`Doukutsu.exe`, `noiz2sa.exe`, `rr.exe`, `wf.exe`, `pq.exe`, `igi.exe`, `TrackEditor.exe`, BusyBox, PuTTY, 70+ Simon Tatham puzzles/solvers, etc.).
- **Concrete remaining gaps discovered in Phase 3 triage:**
  - `tools/lift/eh32.py` (MSVC C++ EH checkpoint detector) was written and self-tested, but never invoked from `tools/lift/translator.py` or `tools/autorecomp/pipeline.py`, and lacked Digital Mars D (`0xE0440001`) exception metadata support (`gr.exe`, `p47.exe`, `tt.exe`, `tf.exe`).
  - Game-target issues `#15`–`#24` still require an owned original-Windows execution harness to generate real gameplay scenario oracles (`divergence.py`, `input_rec.c`).

### Graphics, Audio, Input & Networking Runtimes (`#2`, `#5`, `#6`, `#7`, `#10`, `#11`, `#12`)
- **Implemented (`runtime/win32hle/`):**
  - `ddraw.c`, `d3d7.c` (with `d3d7_selftest.c`), `gl32.c`, `gdidc.c`, `gdi32.c`, `user32.c`, `screen.c` (with Cocoa/Metal/SDL2 presentation).
  - `dsound.c`, `bink.c`, `mss.c`, `sdlmix.c`, `avifil32.c`, `winmm.c`.
  - `dinput.c` (DInput 3/5/7 keyboard & mouse on SDL2). Note `docs/RUNTIME_COMPAT.md` historically lagged behind `host.c`'s actual `dinput.c` registration.
  - `wsock32.c` (Winsock 1.1 TCP/UDP + IPX-over-UDP compatible with Westwood LANs).
- **Missing / Unstarted:** Direct3D 8 (`d3d8.dll`), Direct3D 9 / 9Ex (`d3d9.dll`), Direct3D 10/11 (`d3d10/11.dll`, `dxgi.dll`), Direct3D 1–6 / 3dfx Glide, DirectInput8 / XInput / RawInput / HID, real `waveOut` PCM & MIDI/MCI audio, DirectSound3D spatial audio, DirectShow (`quartz.dll`), Winsock 2 overlapped sockets, and DirectPlay (`dplayx.dll`).

### Multi-Module Execution, SEH/CRT & Architecture Expansion (`#8`, `#9`, `#13`)
- **PE32 multi-module (`#9`):** `module.c` + `pe_loader.c` + `host.c` map static companion DLLs into guest memory (`recomp_companion_list`), run `DllMain`, and resolve exports (verified on Parsec47's `bulletml.dll`: 25 exports, 0 unresolved imports). However, arbitrary runtime-loaded C++ DLLs (`LoadLibrary`), Borland/MSVC/D SEH unwinding (`kernel32_crt.c`'s `RaiseException`), `MSVCP140.dll` (`GeneRally.exe`, `58` unresolved imports), and external MinGW `libstdc++-6.dll`/`libgcc_s_dw2-1.dll` (`Tetris.exe`, `42` unresolved imports) remain incomplete.
- **Win16 NE (`#8`) & Win64 PE32+ (`#13`):** Supporting offline libraries (`tools/ne/`, `runtime/win16/`, `runtime/recomp64_cpu/`) are checked in, but `tools/autorecomp/pipeline.py` intentionally rejects non-PE32 inputs fail-closed until full lifting/ABI pipelines are integrated and tested.
