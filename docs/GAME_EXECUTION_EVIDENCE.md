# One-at-a-time game execution evidence (macOS/arm64)

All runs used `tools/game_runner`, one binary at a time, from the game's own
folder, with `SDL_VIDEODRIVER=cocoa`, `SDL_AUDIODRIVER=dummy`,
`RECOMP_SCREENSHOT=<per-game evidence dir>`, `RECOMP_SCREENSHOT_MAX=3` and a
12-second timeout. Raw logs and frames are under
`test-results/game-matrix/execution/<game>/`, with `summary.json` at the root
of that directory (gitignored, regenerated by the command below):

```
python3 -m tools.game_runner \
  --game gunroar --binary <built>/gr --folder <games>/gunroar \
  --game cavestory --binary <built>/Doukutsu --folder <games>/cavestory \
  --game ikachan --binary <built>/dxIka --folder <games>/ikachan \
  --out test-results/game-matrix/execution --timeout 12
```

## Results actually observed

| Gunroar | `c4a1117c809312e0a844526be7d3bb7c960c23bffeadfae6ded07b5045f49704` | 3 | 0 | **FAIL** — DMD exception unhandled (issue #27) |
| Cave Story | `c6f810f8f5b560e3e6e29cd1cf1e73584febcaa120f68467bfe7f3e56cb7669c` | timeout (stayed alive) | 2 × 640×480 | **PARTIAL** — rendered frames, no gameplay oracle |
| Ikachan | `251b57fb1f2d6e27870a801763e281b0183dc975794782773cf2d7ad978db468` | timeout (stayed alive) | 3 × 351×238 | **PARTIAL** — rendered frames, no gameplay oracle |

### Gunroar
`run.log`:
```
[pe] bound 136 imports, 0 unresolved
[host] C:\gr.exe booted: entry 0x0042D49C, 0 unresolved imports
[win32hle] RaiseException(0xE0440001) from guest 0x0041E110: guest exceptions are not handled
```
The rebuilt binary boots with zero unresolved imports, so the failure is a
guest-exception dispatch defect, not an import-binding failure. Tracked in
issue #27. No frame was produced.

### Cave Story
`run.log` includes:
```
[ddraw] SetDisplayMode(640x480x16)
[screen] cocoa, OpenGL context, scaling sharp (F12), fullscreen F11
[ddraw] CreateSurface 640x480 16 bpp ... primary -> ... ret=0040B450
[screenshot] .../cavestory/screenshots/frame-0000.bmp (640x480 16 bpp)
```
Two 640×480 BMP frames were written and the process remained alive for the
full 12 s. This demonstrates boot + display-mode/surface setup + frame output,
**not** verified gameplay: there is no original-Windows frame comparison and
no input/audio verification.

### Ikachan
`run.log` includes:
```
[screen] cocoa, renderer metal, scaling sharp (F12), fullscreen F11
[screenshot] .../ikachan/screenshots/frame-0000.bmp (351x238 32 bpp)
[screenshot] .../ikachan/screenshots/frame-0001.bmp (351x238 32 bpp)
```
Three 351×238 BMP frames were written and the process stayed alive for 12 s.
Same limitation as Cave Story: no A5+ gameplay acceptance.

## Games not executed

The remaining PE32 x86 games in the corpus were **not run**: their native
builds were SIGKILLed (exit 137) by host memory pressure during compile, so no
binary exists to execute. They are recorded as **BLOCKED (no native binary)**,
not as PASS, FAIL or 100% tested. Re-run `tools.game_matrix --parallel 1
--jobs 1 --no-clean` for each when the host has sufficient resources, then
feed the resulting binary to `tools.game_runner` to obtain the same evidence
format.

Earlier IGI and TrackMania evidence is documented separately in
`docs/GAME_MATRIX.md`, `docs/GAME_TMNF_EVIDENCE.md` and (on
`feature/p10-tmnf-eswc`) `docs/GAME_TM_ESWC_EVIDENCE.md`.

## Honest conclusion

3 games were executed one at a time with logs and screenshots. 2 produced
real frames; 1 hit a known guest-exception defect. This is **not** "100% of all
games tested", and no issue was closed. The runner and its unit tests make
the result reproducible and the missing games measurable rather than hidden.
