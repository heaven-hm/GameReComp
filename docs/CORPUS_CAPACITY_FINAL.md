# Final corpus capacity — issue #130

**Verdict: `CAPACITY_LIMIT`. Issue #130 remains OPEN.** The exact blocker is a
**legal corpus of 10,000 distinct real Windows games is absent**. This document
reports what the checked-in evidence can actually support; it does not claim
that a build, a static parse, or a synthetic fixture is a verified game.

Generated by `tools/corpus_capacity_final.py` into
`proof/corpus-capacity/audit.json`. The audit records the exact SHA-256 of every
input file, so any later edit to a source report is detectable.

`STATIC_OK` means a PE32 file parsed successfully. It is **not** a build and
**not** a launch. `BUILD-ONLY` means a native binary was compiled but no
run/verify stage was executed. `BLOCKED` means no build was produced. None of
these statuses establishes a verified game.

## Counting rules (fail-closed)

- **Dedupe key**: lowercased 64-hex `sha256`, or the sentinel
  `<missing-sha256>` when the field is absent or malformed. Cross-report
  duplicates collapse to one key (e.g. 88 keys overlap between the inventory
  and the static sweep).
- **Synthetic fixtures are not games**: rows whose path contains
  `tests/fixtures`, or that carry `synthetic`/`fixture: true`, are excluded.
  One such row (`tests/fixtures/pe32-minimal.exe`) is present in the static
  report and is excluded.
- **DLLs are not standalone games**: any SHA-256 labelled `kind: dll` in any
  report is excluded (73 keys).
- **No fake PASS**: a row counts as verified only if it has `status: PASS`,
  `verified: true`, a 64-hex `evidence_sha256`, and a non-empty `oracle`. A bare
  `PASS` status is refused and recorded in `refused_pass_rows`. The checked-in
  reports contain zero `PASS` rows of any kind.
- **No built-in paths**: the tool reads only paths supplied on the command
  line; it has no default corpus location and runs no game.

## Reproduce

From the repository root:

```sh
python3 -m tools.corpus_capacity_final \
    --inventory reports/local-games-inventory.json \
    --static reports/pe32-1000-static.json \
    --results reports/b1_results_snapshot.jsonl \
    --target 10000 --out proof/corpus-capacity/audit.json
python3 -m pytest tests/test_corpus_capacity_final.py -q
```

The output is byte-for-byte deterministic for identical inputs (no timestamps,
no absolute machine paths). Tests prove cross-source dedupe, shortfall
arithmetic, tamper detection (changed input bytes change the recorded digests
and counts), refusal of a bare `PASS`, and that only CLI-supplied files are
read.

## Why #130 stays OPEN

Issue #130 asks for a **10,000-game compatibility stress corpus with
fail-closed evidence**. The repository contains at most 640 distinct executable
Windows binaries with a valid SHA-256, and 0 verified games. Acquiring 10,000
legally redistributable, distinct real Windows games together with per-game
oracle/frame evidence is an external prerequisite that cannot be satisfied from
the checked-in reports. `tools/corpus_capacity_final.py` records this as
`CAPACITY_LIMIT` / `LEGAL_CORPUS_ABSENT`; it does not relax the rule to close
the issue.
