# Generated-C → guest-VA source map

A portable, machine-readable report that maps each generated `void
sub_XXXXXXXX(void)` definition and each dispatch-table entry back to the guest
x86 address it was lifted from. It is produced by reading a **generated project
directory** after the fact; it does not change the pipeline, the runtime, or a
single byte of emitted C.

## Provenance

The method is adapted from Stela's `NativeBlock.source_map`
(`Vec<(GuestAddress, usize)>`) and its `validate_source_map_geometry` / geometry
checks, pinned to commit `140ffaf716e2fa8a2f13d55880ca0fc4521df6fe`. Stela
records one native-code offset per guest instruction; because GameReComp emits
C compiled by a host toolchain, the portable analogue is one
`(guest_va, c_file, c_line)` row per recovered function. **No Stela source is
copied** (Stela is GPL-2.0-or-later, GameReComp is AGPL-3.0-only); this is an
original implementation in `tools/autorecomp/source_map.py`, following the same
pattern already used for the fingerprinted artifact cache
(`tools/autorecomp/lift_cache.py`).

## Usage

```sh
# Full generated project (finds src/recomp/gen automatically)
python3 tools/autorecomp/source_map.py \
  --project-dir build/project --output build/project/source_map.json

# Or a bare gen directory; omit --output to emit JSON on stdout
python3 tools/autorecomp/source_map.py --project-dir build/project/src/recomp/gen

# CI-style: fail the step if any named violation is present
python3 tools/autorecomp/source_map.py --project-dir build/project \
  --fail-on-violation >/dev/null
```

The module is also importable:

```python
from tools.autorecomp import source_map

doc = source_map.build_source_map("build/project")
issues = source_map.validate_source_map(doc, "build/project")
stats = source_map.coverage(doc)
```

`--project-dir` accepts a full generated project (`<project>/src/recomp/gen`),
a bare `gen` directory, or any tree containing `recomp_dispatch.c`.

## What is mapped

* Every `void sub_XXXXXXXX(void) { ... }` definition in `recomp_*.c`, including
  the `sub_XXXXXXXX__lowlevel` mechanical fallback kept beside a high-level
  replacement. Braces in comments and string literals are skipped so the
  recorded `end_line` is the real body end.
* Every `{ 0xXXXXXXXXu, sub_XXXXXXXX },` entry in `recomp_dispatch.c`.
* Every `void sub_XXXXXXXX(void);  /* 0xXXXXXXXX */` declaration in
  `recomp_funcs.h` (used as corroborating evidence, not as the authority).

The dispatch table is the authoritative list of recovered functions. The
function-level `source_map` list is the portable counterpart of Stela's flat
`(GuestAddress, native_offset)` vector:

```json
{
  "schema": 1,
  "generator": "GameReComp/source_map.py",
  "gen_dir": "src/recomp/gen",
  "artifact_sha256": "…",
  "files": {
    "src/recomp/gen/recomp_0000.c": {"sha256": "…", "bytes": 1234, "lines": 80}
  },
  "functions": [
    {
      "address": "0x00401000",
      "address_int": 4198400,
      "symbol": "sub_00401000",
      "definition": {
        "address": "0x00401000", "symbol": "sub_00401000", "kind": "entry",
        "file": "src/recomp/gen/recomp_0000.c", "line": 5, "end_line": 10
      },
      "fallback_definition": null,
      "dispatch": {"file": "src/recomp/gen/recomp_dispatch.c", "line": 7,
                   "symbol": "sub_00401000"},
      "header": {"file": "src/recomp/gen/recomp_funcs.h", "line": 5,
                 "symbol": "sub_00401000"},
      "definition_count": 1,
      "dispatch_count": 1
    }
  ],
  "source_map": [
    {"guest_va": "0x00401000", "file": "src/recomp/gen/recomp_0000.c",
     "line": 5, "symbol": "sub_00401000"}
  ],
  "coverage": {
    "mapped": 1, "expected": 1, "definition_count": 1,
    "dispatch_entry_count": 1, "declared_dispatch_count": 1,
    "percent": 100.0, "dropped_addresses": [],
    "unmatched_definition_addresses": []
  },

}
```

## Portability guarantees

* Every path is **relative to `--project-dir`** and uses POSIX `/`
  separators. No absolute paths, user names, Wine prefixes, or host-specific
  data are written, so the report is byte-comparable across machines.
* `files[].sha256` and the top-level `artifact_sha256` bind the report to the
  exact generated bytes it describes; a regeneration changes the hash and
  makes a stale map detectable. (The hash is content-identity, not a
  cryptographic authenticity claim.)
* The report is a generated artefact, never a source file. A readability pass
  or a human edit cannot silently invalidate it: re-running the tool re-reads
  the C from disk.

## Validation

`validate_source_map` returns a list of **named violations** (strings prefixed
`kind: detail`), never a bare boolean, so a caller can fail closed with a
concrete reason. The `violations` field is embedded in the document and
`--fail-on-violation` exits 1 when it is non-empty.

| Kind | Meaning |
| --- | --- |
| `file_missing` | A recorded generated file no longer exists. |
| `file_line_count_mismatch` | The recorded line count differs from the file on disk. |
| `missing_definition` | A dispatch VA has no `void sub_XXXXXXXX` definition (a dropped address). |
| `missing_dispatch` | A definition has no dispatch entry. |
| `unbalanced_body` / `invalid_body_span` | The recorded function body has no matching brace or an invalid line span. |
| `duplicate_entry_definition` | More than one entry body for one VA (a `__lowlevel` fallback is allowed). |
| `duplicate_dispatch` | More than one dispatch entry for one VA. |
| `symbol_address_mismatch` | A dispatch symbol encodes a VA different from its dispatch key. |
| `line_out_of_range` / `unregistered_file` | A file/line row points outside its file or to an unlisted file. |
| `non_monotonic_dispatch_address` / `non_monotonic_dispatch_line` | Dispatch-table geometry is not strictly increasing (Stela-style geometry check). |
| `dispatch_count_mismatch` | `recomp_dispatch_count` disagrees with the number of parsed entries. |

## Coverage

`coverage.mapped` counts VAs that have both a definition and a dispatch entry;
`coverage.expected` is the dispatch-table size. `dropped_addresses` is the Stela
`dropped_addresses` analogue: VAs the dispatcher promises but for which no C
definition was emitted. A clean project reports `mapped == expected`, `percent
== 100.0` and empty address lists.

## Limits / non-goals

* **Function-level, not instruction-level.** Mapping individual guest opcodes
  to C statements would require threading a collector through `lift32.py` and
  `translator.py`; that is a separate, larger change. This tool consumes only
  the generated project directory.
* It reads generated C by pattern, not by compiling it. It proves structural
  consistency and completeness of the map, not semantic correctness of the
  lifted bodies.
* It matches address-named `sub_XXXXXXXX` symbols. Dispatch entries pointing at
  a differently named symbol are still recorded and checked, but no definition
  match is inferred from the name alone.
* No changes to `tools/autorecomp/pipeline.py`; integration (calling the tool
  from a stage) is a deliberate follow-up.
