# Upstream D3D9 reuse audit (issue #5)

This audit records the Direct3D 9 source, licence and reusable logic found in the
`codepdbh` Need for Speed static-recompilation family, for GameReComp's PE32 D3D9
gap (issue #5 in `docs/ISSUES_AUDIT.md`: "`d3d9.dll` / `dinput8.dll` shim
feasibility audit, Need for Speed/similar decomp reference comparison"). It is a
source/evidence review only. It does not claim that any upstream game is
playable under GameReComp, and no code from these repositories was copied into
this branch.

## Pinned sources

commits this audit describes.

The three projects are siblings ("NFS Android Evolved"): NFSU1 and NFS Most
Wanted copy/reuse the NFSU2 runtime. The D3D9 material exists in essentially one
form across them, so `nfsu2-recompiled` is the canonical source for the audit.

### Licence findings (important)

- **No repository contains a `LICENSE` / `COPYING` file.** Licence terms come
  only from README prose and third-party notices.
- `nfsu2-recompiled/README.md` ("Legal & Disclaimer"): "All code authored in
  this repository (lifter tooling, Android bridge, WSI wrappers, launcher and
  scripts) is released under the **MIT License**." MIT is therefore the clearest
  grant in the family, but the canonical MIT text is not checked in.
- `nfsu1-recompiled` has no licence section; its `docs/AUDIT.md` and credits
  describe it as reusing the NFSU2 "MIT project" runtime, and its D3D9 files are
  verbatim copies of NFSU2's. Treat as MIT-authored, with the same missing-text
  caveat.
- `nfsmwpc-recompiled` explicitly defers to per-file licensing and has no D3D9
  implementation of its own (see below). Do not rely on it as a licence source.
- The bundled DXVK under `ports/dxvk_android/` is a **separate third-party
  dependency**, not MIT: `ports/dxvk_android/DXVK-LICENSE` is the zlib/libpng
  licence, Copyright (c) 2017-2021 Philip Rebohle and 2019-2021 Joshua Ashton.
  `THIRD_PARTY_NOTICES.md` (Most Wanted) also carries ThirteenAG's MIT notice for
  widescreen code.
- Consequence for reuse: prefer **independent derivation from the public COM
  ABI and the measured behaviour report** over copying source. If any source is
  lifted, preserve the MIT copyright/permission notice, add a `LICENSES/` entry
  and a `NOTICE` line, and keep the zlib notice with anything DXVK-derived. The
  ambiguity above is a reason not to copy blindly.

## Reuse decision for GameReComp's PE32 D3D9 gap

GameReComp currently has no `d3d9.dll` in `runtime/win32hle/` (see
`docs/ISSUES_AUDIT.md` #5/#7 and the `RUNTIME_COMPAT.md` table: D3D7 is the
ceiling). The precedent to follow is `runtime/win32hle/d3d7.c`: a portable
fixed-function OpenGL facade whose guest-visible COM objects live in guest
memory (`hle_alloc`/`hle_ptr`) and whose exports use the shim ABI. A D3D9 title
needs only `d3d9.dll!Direct3DCreate9` to bind; everything else is reached
through the returned COM vtables.

| Area | Decision | Technical reason |
|---|---|---|
| D3D9 method inventory and vtable slot order (`k_d3d9[17]`, `k_dev[119]`) | **Reuse as a specification; re-derive the tables, do not copy the arrays.** | The slot order is just the documented `IDirect3D9`/`IDirect3DDevice9` COM layout; GameReComp needs the same ordering to build its own vtables. Factual ABI data, but copying the literal arrays from a repo with no clear licence grant is unnecessary — derive them from `d3d9.h`/the public interface definition. |
| `docs/D3D9_USAGE.md` subset (CreateDevice params, states, formats, FVF, primitives, call mix) | **Reuse as evidence and as a test oracle.** | It answers "what must a minimal D3D9 HLE actually implement?" with measurements, avoiding over-building. Use it to scope a first `runtime/win32hle/d3d9.c` (X8R8G8B8 backbuffer, D24S8 depth, `D3DSWAPEFFECT_DISCARD`, `DrawPrimitiveUP`, fixed function + vertex/pixel shaders, state blocks) and to write selftests. Numbers are from the upstream project's own run — verify against any owned target before treating them as truth. |
| Windowed-mode `CreateDevice`/`Reset` presentation-parameter rewrite (`make_windowed`, vtable patching) | **Do not copy; reimplement in GameReComp's terms if needed.** | It is MSVC/Win32-specific (`VirtualProtect`, `SetWindowLongPtrA`, `WNDPROC`) and assumes a real `d3d9.dll` whose vtable can be patched. GameReComp owns the device: present parameters are handled inside its own SDL/GL `d3d9.c`, exactly as `d3d7.c` owns D3D7 state, so no host-side vtable hooking applies. |
| `src/runtime/d3d9_trace.c` as a tracer | **Do not port verbatim. Optional: write a small native observer in `win32hle` using the same idea.** | It is an *observer*, not a renderer, and is coupled to `native32` post-call hooks, `native32_add_name`, upstream logging and widescreen code. Its useful ideas — name vtable slots, count methods, record value sets, flag NaN constants — can be re-expressed with `hle_*` helpers if differential tracing is wanted, but there is no reason to import the file. |
| `android/app/src/main/cpp/d3d9_bridge.*` + `.inc` | **Do not copy (explicit exclusion).** | It is Android/DXVK/JNI glue: `ANativeWindow`/`dxvkAndroid*` calls, a real DXVK `Direct3DCreate9`, upstream guest-heap callbacks, DXT shadow textures and a synthetic token-dispatch ABI. GameReComp targets PE32 on POSIX/SDL2, not DXVK on Android; importing it would also drag in a zlib-licensed dependency and the wrong memory/COM model. |
| `ports/dxvk_android/` | **Do not copy (explicit exclusion).** | Third-party patched DXVK (zlib), Android WSI and driver workarounds. A different portability target and a different licence. |
| DirectInput 8 | **Out of scope for this audit; note only.** | Upstream has a `DirectInput8Create` shim and `dinput_trace.c`, but they are the same native32/Win32 pattern; GameReComp's `dinput.c` covers v3/5/7 and DInput8 would be a separate facade. |

**Net decision:** the upstream family is a *behavioural reference*, not a code
donor. Its D3D9 contribution to GameReComp is the measured subset specification
and confirmation that one `Direct3DCreate9` import is the entry point. The
implementation belongs in a new generic `runtime/win32hle/d3d9.c` following
`d3d7.c` (guest-address COM vtables, `hle_ptr`-based structure access, SDL-owned
OpenGL context, shim-ABI export), driven by selftests, with reuse of the
interface layout and state/format values derived independently from the public
D3D9 ABI. No Android, DXVK, JNI or upstream-guest-heavy code crosses this
boundary.

## Evidence limits

- Sources were read from shallow clones of the default branch; only the exact
  SHAs above were inspected, and no upstream release binary or game asset was
  used. These repositories contain no game files by their own statements.
- `docs/D3D9_USAGE.md` numbers are upstream's measurements of NFSU2's intro
  (1,320 frames), not GameReComp traces and not proof of any target's behaviour.
- A build, a lifted trace or a vtable inventory is not evidence of playable
  rendering. Any future `d3d9.c` must be validated first in GameReComp's Unicorn
  harness/selftests and only then against an owned game/Wine workflow, per the
  repository's verification rules.
- Licence statements are README prose; no repository ships the full MIT text.
  That uncertainty is itself a reason to derive rather than copy, and any future
  copy must preserve notices and add a `LICENSES/` entry plus `NOTICE` line.
